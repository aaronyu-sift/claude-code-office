# Pixel scene plan

Status: plan written 2026-10-28, nothing of the runtime exists yet. This file is the single source of truth for the work;
read it fully before starting, and update the checkboxes and "Decisions" as you go. Branch: `pixel-scene`.

## 1. Goal

Replace the low-poly three.js office (`public/js/ofis.js`, `ofis-env.js`) with a pixel-art scene that is
**exquisite, not low-bit**: rich colour ramps with hue shift, textured surfaces, ambient occlusion, a thin dark outline,
a cheerful chunky Two Point-like mood. It must stay **very readable**: the agents, their status and their full chat
names stand out from the decoration. It must be **cheap to run**: pre-rendered sprites on a 2D canvas, no 3D, only small
items animate. The user can switch between **isometric (2:1)** and **front three-quarter** views.
It also has a **time-of-day light** that follows the local clock and, optionally, **seasons** and **weather** in the spirit of
Animal Crossing: New Horizons. The clock and the seasons are cheap; weather is opt-in and capped.

Out of scope for now: moving cars, the river, any road traffic. Mountains are optional later. The old 3D scene stays
as a fallback (`?scene=3d`) until the user says to remove it.

## 2. Decisions already made (do not re-litigate)

- **Art is generated by us**: voxel models written as code (`tools/sprites/`), rendered with the renderer of
  [VoxPix](https://github.com/andyeswong/voxpix) (MIT; pinned checkout `.tools/voxpix` at commit `c8e9843`, git-ignored).
  VoxPix is used at build time only. The generated atlases and manifest are committed, so the app and `npm test` never need it.
  No third-party art, so no asset licences. If a third-party asset is ever added, record its licence in `THIRD_PARTY.md` first.
- **No WebAssembly, Rust or C++.** The runtime is plain JavaScript modules, zero runtime dependencies, no build step for the app.
  Types via JSDoc, checked with `tsc --noEmit` only if TypeScript is already installed (do not add it as a dependency).
- **Both projections are supported from the start** through one `Projection` interface (section 4). Isometric is the default.
- **Full chat names** are shown on every main agent's label (wrapped, never cut with an ellipsis up to 120 characters).
- **Labels are the density limit, not sprites** (measured with `tools/sprites/density.ts`): give each agent a label slot.
- **Test scale: up to 20 agents, typically 10.** If it works for 20 it is expected to work for more (other people may run more), so the code has no hard cap, but nothing above 20 is tested or tuned.
- **Time, seasons, weather** (user, 2026-10-28). Time of day is always on and follows the browser's local clock: tinted light,
  lit windows, lamps and monitors after dark, a soft sky gradient behind the island; agents and their labels must stay readable at
  night. Seasons are optional and default to automatic by date (northern hemisphere unless set): foliage, flowers, ground and small
  props change, **baked at build time as extra sprites**, not recoloured at runtime. Weather is optional and defaults to **off**:
  clear, cloudy, rain, snow, fog, with a seeded automatic mode per date and season; no network calls and no real-weather API.
  Weather and seasonal particles share one overlay canvas, at most 120 particles, at most 10 fps, zero cost when off, paused when
  hidden, off with `prefers-reduced-motion`. `?time=HH:MM`, `?season=` and `?weather=` override everything for tests and demos.
- Style proof exists: `tools/sprites/diorama.mjs` (iso and oblique renders). Keep the palette and proportions; improve them.
- Commits: repo-local author is already `Aaron Yu <macbookproiceland@gmail.com>`. No Claude co-author trailer, no `#NNN`
  in messages. **Never push** and never open a PR; the user decides that. Do not touch `main`.

## 4. Architecture

Build time (`tools/sprites/`, needs bun and `.tools/voxpix`):

- `models.mjs` objects, `lib.mjs` DSL, one file per category once it grows (`furniture.mjs`, `plants.mjs`, `people.mjs`, ...).
- `build-atlas.mjs [--proj iso|front] [--check]` renders every model at 4 facings (iso: yaw 45, 135, 225, 315 at elevation 30;
  front: yaw 0, 90, 180, 270 with `oblique {y: 0.75, z: 1}`), packs them into `public/pixel/atlas-<proj>.png` and writes
  `public/pixel/manifest.json` (id, rect, pivot pixel, footprint in voxels, height, facing, animation frames, tags).
  `--check` regenerates in memory and fails if the committed atlas or manifest differs (determinism check).
  Workers and chair as one sprite per (appearance, pose, facing); 6 appearances baked via palettes (skin, hair, shirt).
  Wall tints per project colour at runtime (neutral wall sprites tinted on a cached canvas), not baked.

Runtime (`public/js/pixel/`, ES modules, no dependencies):

- `projection.js` exports `ISO` and `FRONT`: `toScreen(x, y, z)`, `toGround(sx, sy)` (inverse, used for hit-testing),
  `depthKey(footprint, z)`, visible wall sides (iso: north and west; front: north only), tile size, facings.
- `atlas.js` loads PNG and manifest, hands out sprite draw info, caches recoloured variants.
- `layout.js` pure function: agents in, `{ rooms, shelf, bounds }` out (rooms with desk slots and label slots; `shelf` is an ordered list that stays empty until Goal 4, so the interface does not change later), deterministic and stable (rooms keep
  their place when others come and go), island bounds including garden. Unit-tested without a browser.
- `scene.js` two layers: a cached static layer (floors, walls, furniture, outdoors; rebuilt only when the layout or zoom
  changes) and a dynamic layer (workers, status effects, ambient animation, redrawn only where needed).
- `anim.js` one scheduler: at most 10 fps, only for sprites on screen, nothing while `document.hidden`, respects
  `prefers-reduced-motion`. Animated items are small: monitor flicker, typing hands, coffee steam, plant sway, clock,
  butterflies and birds (tiny), window lights. No full-scene motion.
- `labels.js` DOM overlay (crisp text, selectable): label slot per agent with the full chat name, tool line, say line,
  wall sign per room with the project name. Collision-free by construction (slots) plus a declutter pass.
- `time.js` pure functions: local time to phase (night, dawn, day, golden hour, dusk), sunrise and sunset by month (simple model), `ambient(t)` colour and intensity.
- `lighting.js` re-tints the cached static layer at most once a minute (multiply with a warm or cool ambient colour, weaker indoors than outdoors so rooms stay readable), then adds emissive lights (windows, lamps, monitors) in an additive pass only for sprites on screen, and draws a sky gradient behind the island. Sun-angle shadows are a stretch.
- `season.js` season from date and hemisphere; picks sprite variants (`<id>@spring|summer|autumn|winter`) from the manifest.
- `weather.js` weather state (seeded by date), one overlay canvas with capped particles (rain streaks, snowflakes, petals, leaves, fireflies), drifting cloud shadows, wet-ground and snow-cover overlays, a fog gradient, a rare rainbow after rain; shares the scheduler with `anim.js`.
- `settings.js` persisted settings (localStorage) merged with URL overrides; a small popover in the header: projection, time (auto or slider), season (auto or fixed), weather (off, auto, fixed), hemisphere.
- `input.js` integer zoom steps in device pixels (1, 2, 3, 4, 6), pan, fit, hit-test through `projection.toGround` and sprite alpha, hover, click.
- `index.js` exports `createPixelOffice(root, ctx)` with the same interface as `createOfis`; `main.js` picks it by default,
  `?scene=3d` picks the old one, `?proj=iso|front` and a toggle button choose the projection (persisted in localStorage).

Rendering rules: canvas drawn at its virtual resolution and scaled by whole numbers with `image-rendering: pixelated`;
`getContext('2d', { alpha: false })`; no allocation in the frame loop; static layer cached per zoom.

## 5. Art direction

- Light from the upper left (VoxPix default). Palette ramps: 5 tones, shadows drift blue-violet, highlights warm.
- Proportions: big heads (Two Point), chunky furniture, saturated but harmonious colour per room (project colour as the accent on walls, rugs, sign).
- Decoration must never fight the agents: agents and their status effects are the highest-contrast, most saturated items; outdoor decoration is slightly lower in contrast; props never stand between the camera and an agent (occlusion budget, section 7).
- Everything on a 16-voxel tile grid; walls 30 voxels high; people about 38 voxels tall.
- Seated workers face the desk. Keep faces readable where the facing allows it.

Content to build (counts are minimums per projection, as manifest ids with tags):
- Floors 8 (carpet teal, gold, project-tintable, wood, tile, checker, hall, outdoor path), walls 14 (plain, window, door, poster x3, clock, whiteboard, notice board, shelf wall, corner, cap, glass).
- Furniture 24: desks (single, L, standing), chairs x3, sofas x2, rugs x3, shelves x2, cabinets, printer, coffee machine, water cooler, server rack, whiteboard stand, lockers, trash bin, reception desk.
- Desk props 14: monitor (3 screen states), laptop, keyboard, mug, plant, lamp, papers, figurine, headphones, sticky notes, books, snack, tablet.
- People: 6 appearances x poses (typing A, typing B, thinking, waiting with raised hand, sleeping, standing) x 4 facings; walker later.
- Plants 12 (pots, hanging, tall, flowers, cactus, bonsai), trees 6 species, bushes 4, hedges, flower beds 4, grass tufts, rocks 4.
- Outdoor 14: bench, lamp post, picnic table, fence pieces, signpost, bike rack, fountain, pond (still water, no river), stepping stones, planters, well, tiny shed, mailbox.
- Status effects drawn in code or small sprites: beam of light, balloons (working, waiting "!", done, sleeping "Zz", error), sparkles.
- **Status language, with The Sims 4 as a design reference** (user, 2026-10-28; reference for patterns only, no copied art or UI): a Sim shows state

  - Goal 5 may use a small radial menu on click (Details, Open in VS Code, Copy session id) in place of the plain drawer, and the details panel may borrow the info-panel idea:

## 7. QA harness and budgets (what "done" means)

`node tools/qa/pixel-qa.mjs [--proj iso|front]` starts the server against a fixture, drives headless Chrome through the DevTools
protocol in a throw-away profile (never the user's live Chrome, never a visible second Chrome), and prints one line per check
`CHECK <name> PASS|FAIL <detail>` and a final `QA PASS` or `QA FAIL`. Checks:

1. No console errors or failed requests on load, at N = 4, 10, 20 (long, wrapped and plain names, emoji, 120 characters).
2. Label text equals the agent's full name for every main agent; no two label boxes intersect; no label leaves the viewport at fit zoom.
3. Every agent has a click target of at least 24 x 24 CSS px at default zoom and the click opens the drawer for that id.
4. Occlusion: for every agent at default layout, at most 15 percent of its sprite pixels are covered by sprites drawn after it.
5. Hit-test round trip: clicking the centre of every agent returns that agent.
6. Frame budget, N = 20, 1500 x 900, 10 seconds: p95 JavaScript time per dynamic frame at most 4 ms; at most 10 frames per second; zero animation callbacks while `document.hidden` (stub `visibilityState`); static rebuild at most 50 ms. These are first targets: if software GL in headless Chrome makes a number meaningless, measure JavaScript time only and say so.
7. Idle: with all agents dormant and nothing animating on screen, zero frames per second.
8. `?scene=3d` renders the old scene without errors.
9. Manifest has no id matching `river|car|road|traffic`.
10. Determinism: `node tools/sprites/build-atlas.mjs --check` passes.
11. Time of day: for `?time=` 06:00, 09:00, 12:00, 18:30, 22:00 and 02:00 the page renders without errors; at every hour each agent sprite's mean luminance is at least 60 percent of its noon value, label contrast is unchanged, and windows, lamps and monitors are lit after dark; the static layer is re-tinted at most once a minute (measure it, at most 15 ms).
12. Seasons: for `?season=spring|summer|autumn|winter` every outdoor sprite id with a seasonal variant resolves in the manifest; the automatic season follows the date and the hemisphere setting (unit test with fake dates, both hemispheres).
13. Weather: with weather off nothing runs on the overlay (zero callbacks); with each weather on, at most 120 particles, at most 1 ms of JavaScript per frame at N = 20, nothing runs while hidden or with reduced motion; the same date and season always give the same automatic weather (unit test); no network request comes from any weather code.
14. Settings: changes apply without a reload, persist across a reload, and URL overrides win over stored settings.

`npm test` (node --test, no browser, no VoxPix) covers projection, layout, scheduler, manifest consistency (every sprite id used by
the code exists), label wrapping.

Safety rules for the work itself: loop or stress pages only in headless Chrome; load-test nothing shared; do not leave servers
running at the end of a turn (stop them by PID); do not push; do not edit anything outside `~/claude-code-office` except the
Drive review folder `My Drive/Agent Chat/pixel-scene/` (HTML and PNG only, served at `http://localhost:8787/Agent%20Chat/pixel-scene/...`;
test every link with curl before giving it).

## 8. Risks

- VoxPix is young and single-author: pin the commit, commit the atlases, keep the models as our own data.
- Depth sorting of large sprites: keep walls in segments of at most 32 voxels and sort by footprint; test with the occlusion check.
- Pixel scale vs screen size: integer zoom only; at fit zoom very large scenes may need pan. Say so rather than blur.
- Label density with full names: slots, wrapping and the declutter pass; if 20 agents cannot fit labels at fit zoom, allow scroll and report it.
- Night readability: agents stay the brightest, most saturated items after dark; rooms are lit and the tint is stronger outdoors; check 11 enforces a luminance floor.
- Weather is the one feature that moves across the whole screen: keep it opt-in, capped and cheap, or it defeats the low-GPU goal.
- Seasonal variants grow the atlas: bake only outdoor sprites, keep the 2.5 MB budget in view.
- Two atlases double art QA: the layout and scene code must not branch on the projection except through `Projection`.

## Deviations

Everything that differs from this plan, by goal. Each entry says what was planned, what was built and why.

### Goal 1

- **Sprite and pose set.** Planned: people with typing A and B, thinking, waiting, sleeping and standing poses at 4 facings. Built: 6 appearances x 5 poses (typeA, typeB, wait, sleep, relax) at one facing each (30 people sprites), because every worker is seated facing a screen and Goal 1 only needs the states working, waiting, dormant and done. Thinking and standing poses and the walker come with the later goals. Atlas totals: 72 sprites (floor 8, wall 8, furniture 14, people 30, plant 3, tree 3, outdoor 6), 83 images, 1024 x 93 px, 18,451 bytes. This meets the Goal 1 minimum (about 60); the full content lists of section 5 are Goal 2.
- **Floor ids.** The carpet floors are called `floor_felt_a` and `floor_felt_b`: check 9 forbids ids matching `car`, which `carpet` contains.
- **Static rebuild time.** Check 6 limits the static rebuild to 50 ms. A warm rebuild of 20 rooms takes 3 to 6 ms, but the very first build (cached canvases for the tints, ground layer) takes about 350 ms in headless Chrome. The check measures the warm rebuild; the cold build happens once per page load and is reported in the check line.
- **Frame budget numbers.** JavaScript time only, in headless Chrome with a software canvas (the plan allows this); frames per second are limited by the scheduler to 10, measured 9.5 to 9.9.
- **Zoom at DPR 1.** Zoom is integer steps in device pixels. In the QA (1500 x 900 at device pixel ratio 1) 4 agents fit at zoom 2 while 10 and 20 agents fit only at zoom 1 (the next step would crop the island); at device pixel ratio 2 the 10-agent scene fits at zoom 3 (measured with the same fixture). Not a bug, the cost of "no blur".
- **Label placement.** Labels carry the full name at every zoom; subagent labels only appear at zoom 3 and above (plan: labels per slot). A label may sit away from its agent when the preferred spot would touch another label; labels treat all agent figures as obstacles (a label never hides the 24 x 24 px click target of an agent when a free spot exists). Pointer events: a label is clickable and opens its agent.
- **Hit-testing priority.** Planned: hit-test through `toGround` and sprite alpha. Built: 1. an opaque pixel of an agent's own sprite, 2. the 24 x 24 px minimum target around the agent's centre (closest first), 3. an opaque pixel of a seated agent's desk, 4. the room (opens its main agent). Rule 2 sits above rule 3 so that two neighbouring agents each keep their target.
- **Extra QA checks.** Besides the numbered checks of section 7, `pixel-qa.mjs` also prints `ux-states` (poses, markers, light beams, balloons and the done transition of a subagent), `ux-hover-tip` and `ux-zoom-pan-fit`, to evidence the Goal 1 scene features. `?scene=3d` (check 8) ignores the old scene's own optional probe of `local/ofis-extras.js`, which is a 404 when the file is absent.
- **QA-only hook.** `root.__pixel` (read-only state for the QA, including `freeze(on)` that stops data syncs while a test clicks around) exists for `tools/qa` and has no use in the app.
- **Light beam.** The beam of a waiting agent is drawn behind the figure, in the depth-sorted pass, not on top: on top it washed out the sprite.
- **Not in Goal 1.** README, `THIRD_PARTY.md`, the projection toggle and the front atlas are Goal 3; the FRONT projection is defined and unit-tested only.
- **Known minor art issue.** The clock wall sprite looks partly drawn in facing 0.
